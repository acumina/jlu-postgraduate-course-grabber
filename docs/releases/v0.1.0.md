# v0.1.0 —— 首个发布版

Chrome MV3 选课插件，**原生 JS 零构建**：抓包学习真实的选课请求 → 模板化后重复发包 → 监控余量与选课 ID → 命中余量自动抢课。

## 适用系统

| | |
| --- | --- |
| 学校 / 系统 | **吉林大学研究生选课系统** |
| 首页（登录入口） | `https://yjsxk.jlu.edu.cn/yjsxkapp/sys/xsxkapp/index.html` |
| **选课页**（引擎真正跑的地方） | `https://yjsxk.jlu.edu.cn/yjsxkapp/sys/xsxkapp/course.html` |
| 生效范围 | **只在 `yjsxk.jlu.edu.cn` 上出现面板**，其它网站完全不动 |

## 会自动开始吗？—— 会

**不需要每次点「启动」。**

| 场景 | 行为 |
| --- | --- |
| 首次装好扩展 | 默认就是"运行中"，**一进入选课页（`course.html`）就自动开始抢** |
| 刷新页面 / 重开浏览器 | 自动恢复继续抢 |
| 掉线后你重新登录（含验证码） | 自动继续，不用手点 |
| **你手动点过「停」** | **不会**自己恢复（主动停机是粘性的 —— 撞上验证码或你收手时，插件不能背着你继续发请求） |
| 在首页 `index.html` 上 | 只有面板，引擎不跑；点进选课页就接着跑 |

## 这个 ZIP 怎么用（3 步）

1. 解压（**解压出来的文件夹就是扩展本体**，`manifest.json` 在根目录）
2. 打开 `chrome://extensions` → 右上角打开「**开发者模式**」
3. 点「**加载已解压的扩展程序**」→ 选解压出来的那个文件夹

然后：

- **打开 `https://yjsxk.jlu.edu.cn/yjsxkapp/sys/xsxkapp/index.html` → 面板 → 设置 → 「载入内置预设」**
  （这一步不能省：不载入预设，面板不会在这个网站上出现）
- 正常登录（含验证码）→ **点进选课页 → 引擎自动开始跑**
- 到「档案」页挑目标（仓库里带了今年课表快照，**选课没开也能先挑**）→ 加入监控即开抢
- 抢课期间**让选课页保持可见**（Chrome 会限制后台标签页的定时器）

## 主要能力

| 能力 | 说明 |
| --- | --- |
| 抓包学习 | 从你浏览器自己的请求里学出提交模板，不用手抄参数 |
| 混合取令牌 | 优先复用页面自己取到的 `csrfToken`，必要时用 UI 点击取（约 70ms） |
| 余量监控 | 解析查询响应，命中余量立即提交；也支持不等名额直接高频轮询 |
| 已选课程核对 | 以服务器「已选课程」列表为**权威判据**确认是否选上（响应文案认不出来也能确认） |
| 掉线自愈 | 401/页面文字双路检测，掉线后自动继续；**只在真掉线时**打开登录页（且已开着就切过去） |
| 课程档案 | 离线课表快照，选课未开先挑目标；跨年教学班代码变了按**课程名模糊找回** |
| 同名班策略 | 同名教学班可以一起抢（多一个班多一次机会）；默认**不**因"判定抢到"就停掉其它同名班 |

## 安全与合规（请先读）

- 插件跑在**你自己的浏览器**里，复用你本来就会发出的请求，**不包含任何绕过登录验证（如验证码识别）的功能**
- 这类行为**很可能与学校的选课系统使用条款、教务规定相冲突**，也可能触发风控 —— 风险与合规责任由使用者自负
- 抓包与日志**只存在本地**（`logs/` 已被 `.gitignore` 排除）；推送/导出时会自动脱敏（密码/验证码/学号/Cookie → `***`）
- 本仓库**不含任何个人信息**，附带的是学校**公开课表快照**

## 校验

- 117 项自测：`npm test`
- 无 Node 也能用（扩展本身零依赖）；跑测试/工具才需要 Node ≥ 18

## 已知限制

- 会话是短命的（实测约 9～14 分钟），掉线后需要你**手动输验证码**重新登录再自动继续
- Chrome 会限制后台标签页的定时器（每分钟 1 次）—— **抢课期间请让页面保持可见**
- 提交判定的文案来自抓包，各校/各系统版本可能不同：设置页可改 `submit.rules`
