Chrome MV3 选课插件，**原生 JS 零构建**。这一版的主题是：**把"第一次手动操作"也去掉**。

## 适用系统

| | |
| --- | --- |
| 学校 / 系统 | **吉林大学研究生选课系统** |
| 首页（登录入口） | `https://yjsxk.jlu.edu.cn/yjsxkapp/sys/xsxkapp/index.html` |
| **选课页**（引擎真正跑的地方） | `https://yjsxk.jlu.edu.cn/yjsxkapp/sys/xsxkapp/course.html` |
| 生效范围 | **只在 `yjsxk.jlu.edu.cn` 上出现面板**，其它网站完全不动 |

## 这一版新增：明年 / 换电脑的零手动流程

教学班 ID 每年都变（形如 `20261-101-A0162101001-1785413134156`），
所以跨年能带走的只有**课程名**。新增「**备选清单**」承载它：

### 今年做一次（2 分钟）

1. 档案页搜到想选的课 → 勾选 → **「加入备选清单（明年自动找回）」**
   （只记 课程名/教师/校区，不记教学班 ID）
2. 点 **「复制为配置片段（贴进项目配置文件）」** → 替换
   `kx-config-吉大研究生选课.json` 里的 `"wishlist"` 字段 → 保存

### 明年 / 新电脑（**只有登录是手动**）

```
装扩展（解压 → 加载已解压的扩展程序）
   ↓ 自动：读取项目配置 → 备选清单变成「按名字监控」的目标
打开首页登录（输验证码 —— 唯一的手动步骤）
   ↓ 自动：点进选课页 → 拉一次全量课表
   ↓ 自动：按「课程名＋教师＋校区」模糊匹配今年的教学班
           （相似度不够也采用最像的那个 = **最大兜底**：
             多抢一门只是退一次课，匹配不到就整轮错过）
   ↓ 自动：加入监控并开始抢
```

**中间不需要你点任何按钮。** 目标列表里那些「还没有教学班ID」的条目是**正常状态**，
面板会用绿框写清楚"这是等选课页拉课表后自动匹配"。

## 其它改进

- **快速开始从 4 步降到 2 步**：项目里的配置文件会在扩展启动时**自动应用**，
  不用再手动点「载入内置预设」、也不用导入 JSON
- 修一个真 bug：按课程名解析结果时原来按 ID 回写，多个「待解析」目标会被全部写到
  同一个目标上 —— 现在按下标回写
- 目标页新增「待解析」提示；档案页新增备选清单区块与清空/生成按钮

## 这个 ZIP 怎么用（3 步）

1. 解压（**解压出来的文件夹就是扩展本体**，`manifest.json` 在根目录）
2. 打开 `chrome://extensions` → 右上角打开「**开发者模式**」
3. 点「**加载已解压的扩展程序**」→ 选解压出来的那个文件夹

然后打开首页 → 正常登录（含验证码）→ **点进选课页 → 引擎自动开始**。
抢课期间**让选课页保持可见**（Chrome 会限制后台标签页的定时器）。

## 会自动开始吗？—— 会

| 场景 | 行为 |
| --- | --- |
| 首次装好扩展 | 默认就是"运行中"，**一进选课页（`course.html`）就自动开始抢** |
| 刷新页面 / 重开浏览器 | 自动恢复继续抢 |
| 掉线后你重新登录（含验证码） | 自动继续，不用手点 |
| **你手动点过「停」** | **不会**自己恢复（主动停机是粘性的 —— 撞上验证码或你收手时，插件不能背着你继续发请求） |
| 在首页 `index.html` 上 | 只有面板，引擎不跑；点进选课页就接着跑 |

## 安全与合规（请先读）

- 插件跑在**你自己的浏览器**里，复用你本来就会发出的请求，**不包含任何绕过登录验证（如验证码识别）的功能**
- 这类行为**很可能与学校的选课系统使用条款、教务规定相冲突**，也可能触发风控 —— 风险与合规责任由使用者自负
- 抓包与日志**只存在本地**（`logs/` 已被 `.gitignore` 排除）；推送/导出时自动脱敏（密码/验证码/学号/Cookie → `***`）
- 本仓库**不含任何个人信息**，附带的是学校**公开课表快照**

## 已知限制

- 会话是短命的（实测约 9～14 分钟），掉线后需要你**手动输验证码**重新登录再自动继续
- Chrome 会限制后台标签页的定时器（每分钟 1 次）—— **抢课期间请让页面保持可见**
- 提交判定的文案来自抓包，各校/各系统版本可能不同：设置页可改 `submit.rules`
