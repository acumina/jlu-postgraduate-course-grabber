Chrome MV3 选课插件，**原生 JS 零构建**。这一版修掉「档案」页每行**「加监控」点了没反应**。

## 这一版修了什么

### 「加监控」点击没反应（用户实测报告）

按钮写的是 `data-act="arch-add"`，但事件处理器里**只有** `case 'add-target'`
（那是「目标」页的按钮）→ 点击落到 `switch` 的 `default` → **什么都不发生，也没有任何提示**。

**修**：接住 `arch-add`，与「目标」页同一段逻辑。

**为什么它能活这么久**：之前的测试只检查"按钮**存在**"，没检查"按钮**有人接**"。
这一版补了两条防呆测试，把整类问题堵住：

| 新测试 | 防的问题 |
| --- | --- |
| 每个 `<button>` 的 `data-act` 都必须有对应的 `case` | 按钮点了没反应 |
| 面板调用的每个 `app.xxx` 都必须在门面里存在 | 点了在控制台抛 TypeError，用户更看不到 |

两条都做了**反向验证**（把按钮名/方法名改坏 → 测试立刻失败）。
其中第一条上线时又抓出 9 个"疑似死角"，核对后确认是 `input`/`textarea`
（用 `data-act` 做 `querySelector` 查询，本来就不需要 `case`），已把检查限定在 `<button>`。

## 怎么用（3 步，只有第 2 步需要你动手）

1. **装扩展**：解压 ZIP → `chrome://extensions` → 打开「开发者模式」→
   「加载已解压的扩展程序」→ 选解压出来的文件夹
2. **打开首页登录**（含图形验证码）—— **唯一的手动步骤**
3. **点进选课页** → 之后全自动：取 `csrfToken` → 拉课表 → 匹配目标 → 余量监控 → 命中就提交

> 抢课期间**让选课页保持可见**（Chrome 会把后台标签页的定时器压到每分钟 1 次）。

## 从零开始的完整流程

```
装扩展（解压 → 加载已解压的扩展程序）    ← 不用配白名单、不用导入配置
   ↓ 自动：应用项目配置/内置预设 → 自动读取项目里的课表快照
打开首页登录（输验证码）                 ← 唯一手动步骤
   ↓ 自动：全新环境时展开面板并切到「档案」页，让你从去年的课表里挑课
   ↓ 自动：点进选课页 → 拉全量课表 → 按「课程名+教师+校区」模糊匹配（最大兜底）
   ↓ 自动：加入监控 → 取 token → 模拟发包抢课
```

**挑课的两种方式**：① 每行点「加监控」（这一版修好的）；② 勾选多行后点
「把勾选的加入监控」；想跨年带着走就用「加入备选清单」。

## 安全与合规（请先读）

- 插件跑在**你自己的浏览器**里，复用你本来就会发出的请求；**不包含任何绕过登录验证（如验证码识别）的功能**
- 这类行为**很可能与学校的选课系统使用条款、教务规定相冲突**，也可能触发风控 —— 风险与合规责任由使用者自负
- 抓包与日志**只存在本地**（`logs/` 已被 `.gitignore` 排除）；推送/导出时自动脱敏
- 本仓库**不含任何个人信息**；附带的 `archives/` 是学校**公开课表快照**
