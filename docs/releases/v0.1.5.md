Chrome MV3 选课插件，**原生 JS 零构建**。这一版修掉一个**数据丢失级**的 bug 和一个**死锁** ——
都是"从零开始"路上才会踩到的。

## 这一版修了什么

### ① 数据丢失：「往年课加完监控，进选课页面突然没了」

`snapshot()` 的实现是 `cache || defaults()` —— **没 load 过就返回空默认值**。
而启动流程原来是：

```js
await autoApplyBundledConfig()   // ← 这时还没 load 过
await ensureSiteConfigured()     //   → 读到的"当前配置"是空的（sites:[] targets:[]）
const cfg = await KX.load(true)  // ← 配置到这里才真正读进来
```

于是每次页面加载：

```
sites 判空 → 判定"这个站点还没配" → 又自动应用一次预设
          → 应用时"保留用户数据"保留的是空数组 → 把空 targets 写回存储
```

**每次导航都会再抹一遍** —— 你从登录页进选课页，就是一次页面加载，目标就没了。

**修**：启动顺序改成 **先 load → 再自动应用 → 再 load 一次**；
两个函数内部也各自先 `KX.load(true)`（纵深防御，换个调用点也不会出事）。

### ② 死锁：只有「待解析目标」时引擎拒绝启动

```js
const targets = cfg.targets.filter(t => t && t.id && ...)   // ← 只认有 ID 的
if (!targets.length) return { ok:false, error:'还没有监控目标' }
```

备选清单生成的目标 **ID 是空的**（等着按课程名解析）→ `start()` 拒绝启动 →
不轮询 → `cycle()` 不跑 → 不触发解析 → **那些目标永远拿不到 ID**。

**修**：「待解析目标」也算有效目标；只有两者都为空才算"没有监控目标"。

### ③ 顺手：载入内置预设不再清空目标

「设置 → 载入内置预设」以前提示"目标列表会清空"。现在只覆盖**系统协议**部分
（站点/接口/判定规则/页面限制），你的**监控目标、备选清单、调速、通知偏好全部保留**。

## 怎么用（3 步，只有第 2 步需要你动手）

1. **装扩展**：解压 ZIP → `chrome://extensions` → 打开「开发者模式」→
   「加载已解压的扩展程序」→ 选解压出来的文件夹
2. **打开首页登录**（含图形验证码）—— **唯一的手动步骤**
3. **点进选课页** → 之后全自动

**档案页挑课的三种方式**：① 每行「加监控」；② 勾选多行 → 「把勾选的加入监控」；
③ 想跨年带着走就用「加入备选清单」。

> 抢课期间**让选课页保持可见**（Chrome 会把后台标签页的定时器压到每分钟 1 次）。

## 安全与合规（请先读）

- 插件跑在**你自己的浏览器**里，复用你本来就会发出的请求；**不包含任何绕过登录验证（如验证码识别）的功能**
- 这类行为**很可能与学校的选课系统使用条款、教务规定相冲突**，也可能触发风控 —— 风险与合规责任由使用者自负
- 抓包与日志**只存在本地**（`logs/` 已被 `.gitignore` 排除）；推送/导出时自动脱敏
- 本仓库**不含任何个人信息**；附带的 `archives/` 是学校**公开课表快照**
