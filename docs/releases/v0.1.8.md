Chrome MV3 选课插件，**原生 JS 零构建**。这一版：**修一个会让抢课停摆的取 token bug**，
加了一个**「模拟明年」自测**，并把**默认轮询速率**提上去。

## 修复：取 token 不再依赖某一门课（会让抢课直接停摆的那个）

**现象**：插件平时用最快的 API 直接发包；取不到一次性参数 `csrfToken` 时，
会让**页面自己点一次「选课 → 确定」**把 token 喂进来。
但原来的实现是**只在某个特定目标的那一行**找「选课」按钮 ——
如果监控列表里没有那门课（或它的按钮不在当前页面），就会：

```
找不到按钮 → 取不到 token → 引擎直接停下 ✗
```

**修**：找不到「本目标」那一行的按钮时，**改用页面上任意一门课的按钮**取 token，
并在日志里写明这次点击的副作用：

> 没找到本目标的「选课」按钮（…）→ 改用页面上任意一门课的按钮取 token
> （这次点击是真实提交，可能顺手选中那门课，不想要就退掉）

**取舍**：多选中一门可以退（可逆），而取不到 token 直接卡死会让整轮抢课停摆（不可逆）。
想关掉这个兜底：设置里 `ui.tokenFromAnyRow = false`（那样找不到本目标的按钮就仍会停下）。

## 为什么需要它

**今年教学班 ID 还有效时，解析走的是「ID 直接命中」这条路 —— 模糊匹配那段代码根本不会被执行**，
所以没法判断它明年到底能不能工作。

## 怎么用

面板 →「**档案**」页 → 点 **「模拟明年（测试模糊匹配能不能生效）」**

它会：

1. 拿你档案里的课表，把所有教学班 ID 改造成**明年样式**
   （`20261-101-A0162101001-1785413134156` → `20271-101-A0162101001-<新尾段>`），
   名字/教师/校区/时间**保持不变**
2. 用这份"明年课表"对你现有的监控目标跑一遍**完整匹配流程**
   （含阈值、最大兜底、全部命中展开）
3. 逐条告诉你结果：命中几个班、最像的是谁、相似度多少、是不是兜底

**它不写任何数据** —— 真实目标、ID 一个都不动，纯粹是拿假课表试跑。

### 实测结果（拿本仓库的 148 门档案造 20271 课表）

| 目标 | 结果 |
| --- | --- |
| 篮球 | ✅ 命中 **14 个班**（全部展开） |
| 钢琴艺术赏析 | ✅ 命中 3 个班 |
| 健美操 | ✅ 命中 2 个班 |

| 档案里没有的课 | ❌ 正确报"未命中" |

## 顺带说明档案的范围

档案 = 学校「**可选课程**」列表的快照 → **已经选上的课不会出现在里面**（学校系统行为）。
想确认某门课选上没有，看「目标」页的**已选课程**区块（服务器权威数据）。

## 怎么用（3 步，只有第 2 步需要你动手）

1. **装扩展**：解压 ZIP → `chrome://extensions` → 打开「开发者模式」→
   「加载已解压的扩展程序」→ 选解压出来的文件夹
2. **打开首页登录**（含图形验证码）—— **唯一的手动步骤**
3. **点进选课页** → 之后全自动：取 `csrfToken` → 拉课表 → 按课程名匹配（全部命中都要）
   → 余量监控 → 命中就提交

## 安全与合规（请先读）

- 插件跑在**你自己的浏览器**里，复用你本来就会发出的请求；**不包含任何绕过登录验证（如验证码识别）的功能**
- 这类行为**很可能与学校的选课系统使用条款、教务规定相冲突**，也可能触发风控 —— 风险与合规责任由使用者自负
- 抓包与日志**只存在本地**（`logs/` 已被 `.gitignore` 排除）；推送/导出时自动脱敏
- 本仓库**不含任何个人信息**；附带的 `archives/` 是学校**公开课表快照**
