# mock —— 本地模拟教务系统

一个零依赖的假教务系统，用来**在碰真学校系统之前**把整条链路跑通。
它复刻了真系统里最容易让插件出错的三件事：

| 模拟的行为 | 用来验证插件什么 |
| --- | --- |
| 登录满 N 分钟**硬超时**，到点所有接口 302 跳 `/login` | 掉线检测、自动停机、重新登录后自动继续 |
| `选课成功` / `人数已满` / `教学班不存在` 三种文本响应 | `submit.rules` 判定规则、已满退避 |
| 对同一门已满的课连刷 3 次后返回 `请输入验证码` | `stopOn.captcha` 自动停机、桌面+声音提醒 |
| 「数据结构」每 20 秒自动放出 1 个名额 | 「查询到余量 → 模拟发包 → 抢到」完整闭环 |

## 启动

```powershell
node mock/server.mjs                       # http://127.0.0.1:8787，硬超时 20 分钟
node mock/server.mjs --port 9000 --ttl 120 # 端口 9000，登录 2 分钟就被踢（方便测掉线）
node mock/server.mjs --no-auto-open        # 关掉「自动放名额」
```

## 5 分钟跑通全流程

1. `node mock/server.mjs` 启动假系统。
2. 浏览器打开 `http://127.0.0.1:8787`，点 **一键登录**（模拟真系统的统一身份认证跳转）。
3. 点插件图标 → **把当前站点加入白名单** → 刷新页面。页面右上角会出现面板。
4. 在假系统的选课页点 **手工查询余量**，再点 **手工选课** —— 这两次请求会出现在面板「抓包」页。
5. 抓包页里点「手工选课」那条 → **设为提交模板**（会自动把 `jxb_id` 换成 `{{id}}`）；
   点「手工查询余量」那条 → **设为余量查询模板**。
6. 「目标」页粘贴两行：

   ```
   2099000001,数据结构（等自动放名额）
   2099000003,编译原理（永远满，用来测验证码停机）
   ```

7. 「抓包 → 启动」。观察：`编译原理` 会先被判「已满」，连刷 3 次后触发验证码并**自动停机 + 响铃**；
   `数据结构` 每 20 秒放出 1 个名额，出现后应当被**自动抢到**。
8. 想测掉线恢复：用 `node mock/server.mjs --ttl 120` 启动，等 2 分钟，
   面板会提示掉线并停止；点 **打开登录页** 重新登录一次，插件应当**自动继续**（`session.autoResume`）。

## 服务端状态

`http://127.0.0.1:8787/__state` 返回当前会话剩余时间、各教学班余量、每个 ID 被刷了多少次，
以及最近的请求日志 —— 排查「插件到底发了什么」时很有用。

## 注意

- 所有数据都在内存里，重启进程即重置。
- 它只监听 `127.0.0.1`，不对外暴露。
- 这个假系统的字段名（`jxb_id` / `kch_id` / `kcmc` / `remain`）是照国内教务系统常见命名写的，
  所以用它练熟的操作，换到真系统上基本一致 —— 但真系统的字段名还是要以你自己的抓包为准。
